# Standalone kernel build and CI

The scripts build the pinned `hotdog` kernel on **Linux x86_64**; they do not build a full crDroid ROM. For the separate official full-ROM workflow, board constraints and upstream toolchain selection see [CRDROID_17_BUILD_REFERENCE.md](CRDROID_17_BUILD_REFERENCE.md).

## Profiles

| Profile | Additional requested features | Validation status |
| --- | --- | --- |
| `baseline` | Pinned crDroid kernel, `vendor/sm8150-perf_defconfig` and `vendor/oplus.config` | Reference build, not flash-proven |
| `core` | Base plus core NetHunter config fragment (e.g. RFCOMM, USB serial/ACM/ECM) | Experimental |
| `external` | `core` plus selected in-tree USB Wi-Fi drivers (`ath9k_htc`, `carl9170`, `rtl8187`, `mt7601u`, `rt2800usb`) | Experimental; firmware, monitor mode and injection **not verified** |

The [NetHunter feature matrix](NETHUNTER_FEATURES.md) gives exact scope. Neither configuration merging nor successful compilation demonstrates device or peripheral operation.

## Prerequisites

Use a native Linux x86_64 host or WSL2 with a Linux filesystem. The tested workflow currently selects Ubuntu 22.04 tools including Clang 14; it is **not** an exact recreation of the official ROM compiler. Install the required executables:

~~~bash
sudo apt-get update
sudo apt-get install -y git make bc bison flex python3 build-essential \
  libelf-dev libssl-dev binutils kmod clang-14 lld-14 llvm-14 \
  gcc-aarch64-linux-gnu gcc-arm-linux-gnueabi
~~~

The older Qualcomm Kbuild scripts sometimes invoke unsuffixed `llvm-ar` / `llvm-nm`. `scripts/build.sh` prepends `/usr/lib/llvm-14/bin` when `CC=clang-14`, or respects an explicit `LLVM_TOOLCHAIN_BIN`. Keep LLVM utilities from a consistent installation.

## Fetch and validate configuration

From the repository root:

~~~bash
bash scripts/fetch-source.sh
CONFIG_ONLY=1 bash scripts/build.sh baseline
CONFIG_ONLY=1 bash scripts/build.sh core
CONFIG_ONLY=1 bash scripts/build.sh external
python3 -m unittest discover -s tests -v
~~~

`fetch-source.sh` checks out the exact SHA in [`config/upstream.lock`](../config/upstream.lock) under ignored `.work/kernel`. A dirty upstream tree is rejected. The build merges the vendor base defconfig and **then** the OPlus overlay before profile fragments and validates the resolved Kconfig. `CONFIG_ONLY=1` writes config evidence only; it produces **no Image, DTB or module**.

## Compile a selected profile

~~~bash
CC=clang-14 LD=ld.lld-14 AR=llvm-ar-14 NM=llvm-nm-14 \
  OBJCOPY=llvm-objcopy-14 OBJDUMP=llvm-objdump-14 STRIP=llvm-strip-14 \
  bash scripts/build.sh baseline

# Alternatively replace baseline with core or external.
~~~

Optionally set `JOBS` to control parallel Kbuild jobs. The script enforces a supported host, cleans the profile's build/output directories, compiles `Image dtbs modules` and performs mandatory artifact audits.

## What is generated?

Output directory: `.work/artifacts/<profile>/`.

| Artifact | Purpose |
| --- | --- |
| `Image` and `dtbs/` | Raw compiled kernel and DTBs; **not a packaged boot image** |
| `kernel.config`, `kernel.release`, `upstream-commit.txt` | Resolved Kconfig, kernel release and source identity |
| `modules/`, `Module.symvers`, `modules.order`, `System.map` | Rebuilt/staged modules and available build metadata |
| `artifact-report.json`, `toolchain-report.json` | Structural, toolchain and module inventory reports |
| `signing-cert.x509`, `signing-cert.sha256`, `build-module-cms.json` | Public build certificate, fingerprint and signature-consistency audit |
| `SHA256SUMS` | Build artifact member checksums |

Some metadata files are emitted only when generated by Kbuild. Exact manifest membership is determined by the build, not this table.

### Module staging and signing

On this 4.14 tree, a raw `make modules` copy is **not** a valid signed installation. `scripts/build.sh` stages `modules_install` with `INSTALL_MOD_STRIP=1`: Kbuild copies, strips debug sections and **then signs** each final module. The script requires `CONFIG_MODULE_SIG_ALL=y` and rejects missing signatures/debug-section issues via `scripts/audit-artifacts.py`. It independently checks the staged module CMS signatures against the **public certificate generated for that build** via `scripts/verify-build-module-cms.py`.

Never strip or rewrite a signed `.ko` afterward. The **private** generated `certs/signing_key.pem` stays in ignored build output and must never be uploaded. Signatures that verify against a *newly generated build certificate* still do **not** prove the **installed ROM kernel** trusts that key. Do not interchange modules signed by different builds. The canonical measured differences and outstanding ABI/provenance gates are in [HARDWARE_EVIDENCE.md](HARDWARE_EVIDENCE.md) and [MODULE_ABI_AUDIT.md](MODULE_ABI_AUDIT.md).

## GitHub Actions behavior

Workflow: [`nethunter-kernel.yml`](../.github/workflows/nethunter-kernel.yml).

| Trigger | CI work | Published artifacts |
| --- | --- | --- |
| Push to `main` / `feature/**` | Shell syntax, Python unit tests, pinned lock checks | No full kernel build required |
| Pull request | Lint plus independent experimental `core` / `external` builds | Bounded JSON/config/public-cert attestations |
| Manual dispatch | Lint plus one chosen `baseline` / `core` / `external` build | Bounded report **and** raw experimental build artifacts |
| Build failure | Restricted diagnostics | Recent log tail and available `.config` only |

Artifacts expire under workflow retention. A workflow run must be inspected for its actual result; a historical PASS does not automatically apply to a later commit. On successful full builds the raw artifacts are **NOT FLASHABLE**, whether module signing and cryptographic checks pass or not. [Release gates](FLASHING.md).
