# Safety gate: NOT YET FLASHABLE

The output is a raw kernel payload and unsigned/rebuilt module set, **not** a functional boot image or certified NetHunter kernel. No script in this project flashes a device.

## Exact installed device and ROM

A read-only version and slot check is provided:

    bash scripts/device-audit.sh

For troubleshooting, the equivalent commands can be executed individually:

    adb shell getprop ro.product.device
    adb shell getprop ro.build.version.release
    adb shell getprop ro.build.fingerprint
    adb shell getprop ro.boot.slot_suffix
    adb shell uname -a

Only proceed later if device is `hotdog` and Android is 17; do not use this for `hotdogg` 5G McLaren. Confirm the exact installed crDroid build and kernel commit before packaging.

## Boot configuration verified against 17.0 device tree

* `BOARD_BOOT_HEADER_VERSION := 2`
* `BOARD_KERNEL_IMAGE_NAME := Image`
* `BOARD_KERNEL_SEPARATED_DTBO := true`
* `BOARD_INCLUDE_DTB_IN_BOOTIMG := true`
* `BOARD_RAMDISK_USE_LZ4 := true`
* `TARGET_KERNEL_CONFIG := vendor/sm8150-perf_defconfig vendor/oplus.config`

Any packaging must preserve the **exact** installed ROM's boot image metadata, DTB/DTBO and ramdisk. Android 17 does not imply a modern GKI vendor_boot layout for this 2019-launched device.

## Confirmed baseline limitation

In GitHub Actions run [39975157488](https://github.com/mason82-dotcom/OP7T-Kernel/actions/runs/39975157488), the original baseline compiled, but the artifact audit saw **2 kernel modules and 0 module signatures** because raw built `.ko` files were copied without Kbuild's `modules_install` signing stage. The follow-up now stages `modules_install` using the new kernel build's own autogenerated signing key, then validates the signers. This establishes only build-level signature preparation and is **not proof of compatibility with an already-installed ROM**. Treat unsigned modules as a runtime load blocker. The updated `artifact-report.json` sets `module_signature_load_blocked` whenever unsigned modules coexist with enforced signatures. Do not disable module signature enforcement as a workaround.

## Build-generated certificate and installed ROM trust

For `CONFIG_MODULE_SIG_FORCE=y`, signing with the certificate generated during kernel compilation works only if the *running kernel* trusts the certificate. New builds generate their own certificate, and old vendor `.ko` files may depend on the old kernel's key or module ABI. Thus stage and sign rebuilt modules **with their matching kernel**, and audit *all* required vendor modules and the exact ROM installation paths. Never ship `certs/signing_key.pem` or a private key in a public artifact. The `signing-cert.sha256` report is a public fingerprint, not the private signing key. CI builds, even signed, are never flash-ready.

## Major blocker: kernel modules

The vendor overlay sets `CONFIG_QCA_CLD_WLAN=m`; the base defconfig sets `CONFIG_MODULE_SIG_FORCE=y`. Existing ROM `wlan.ko` or `vendor_dlkm` modules can refuse to load after a rebuilt kernel due to signatures, vermagic or ABI. Do not disable signature enforcement just to bypass this check. A verified compatible and correctly signed module deployment plan is a separate release requirement.

## Build-to-ROM provenance lock

`config/rom-reference.json` records the public crDroid 13 `hotdog` OTA package released on **2026-10-21** and its published SHA-256. This is a **reference**, not proof that a connected phone is running that exact build. A downloaded ROM ZIP can be verified offline with:

    python3 scripts/verify-rom-zip.py crDroidAndroid-17.0-20261021-hotdog-v13.0.zip

Only the exact installed build's original boot/DTBO and vendor modules can serve as compatibility references for any boot image packaging. The checksum verification script does not extract, patch or flash the ZIP.

## Additional build artifact audit

The generated `artifact-report.json` records the Image header, source SHA, DTBs, module hashes, vermagic, signer identity, signature key ID and algorithm. It verifies **build-internal** module release consistency and requires the Qualcomm WLAN module. The optional `Module.symvers` and `System.map` are retained for detailed local investigation. **Even signed modules may fail to load** if the certificate is not trusted by the exact running kernel. A successful audit is a raw-build check, not a flash certification. `flash_ready` is always `false`.

## Read-only original ROM module comparison

With the exact installed ROM's original `wlan.ko` available locally, run `scripts/compare-rom-modules.py` with `--built` and `--rom` paths. Compare `vermagic` and signer/key identifiers; mismatches are blockers, matching values are **not approval**. The script neither extracts the installed ROM nor writes to the device. Check the *actual* trusted module certificates and symbol ABI separately before image packaging.

## Original boot.img v2 structure audit (read only)

The device board configuration declares `BOARD_BOOT_HEADER_VERSION=2`, `BOARD_KERNEL_PAGESIZE=4096`, `BOARD_INCLUDE_DTB_IN_BOOTIMG=true` and a raw `Image`. Given the original `boot.img` from the exact installed build:

    python3 scripts/audit-bootimg.py /path/to/original-boot.img --expect-sha256 <known_original_sha256>

The script validates the **v2 structure only**: ARM64 Image magic, embedded FDT magic, section size, offsets and SHA-256. It prints bounded JSON and neither extracts nor modifies the input. If the ROM differs from board assumptions, fail and investigate; **do not** force it to pass, and do not flash any generated output. This is not a verified repack, AVB check, device-slot check or compatibility sign-off.

## Live ROM inventory without root

After USB debugging has been authorized on the **OnePlus 7T Pro hotdog**, run `bash scripts/device-module-audit.sh` from a machine with Android Platform Tools. The command repeats `scripts/device-audit.sh` and prints the ROM and vendor fingerprints, Android security patch, verified-boot state and ADB-readable module paths. If `wlan.ko` is readable, the device calculates its SHA-256 without uploading the original binary or writing to the phone. Nonstandard or inaccessible paths are recorded as **unknown**, not absence. It cannot obtain the private signing key, verify ABI or imply boot compatibility.

## ROM identity property semantics (crDroid 17.0 branch)

The crDroid `vendor/lineage/config/version.mk` declares `PRODUCT_VERSION_MAJOR=17` and `CR_VERSION=13.0`. Consequently `ro.crdroid.version=17.0` is the **Android platform version**, while `ro.crdroid.build.version=13.0` is the **crDroid release**. Earlier script warnings comparing `ro.crdroid.version` with `13` were false positives; both audit scripts now query the correct property. A stock Android-12 `ro.build.fingerprint` must not be assumed to identify the installed ROM image. Exact boot/DTBO, module certificate trust and ABI are still unresolved.

## Windows PowerShell read-only audit (without Bash)

The new `scripts/device-evidence.py` uses Python 3 and `adb` (Android Platform Tools) directly, so it avoids CRLF problems from executing Bash scripts on Windows. To collect non-secret ROM/module metadata locally:

    py -3 scripts/device-evidence.py --output hotdog-device-evidence.json

The file is ignored by Git and will **not** be overwritten. The device guard recognizes both `hotdog` and its stock/OEM `OnePlus7TPro` property alias, but NOT `hotdogg` / 5G McLaren. This is only an inventory guard, not a device identity or boot image certification. No ADB root, file pull/push, or flashing occurs. Missing/inaccessible WLAN modules are not evidence of absence. Kernel-signing key trust, verified original boot images, vendor module symbol ABI and device hardware acceptance remain open.

## WLAN module access uncertainty

On an actual OnePlus 7T Pro, `/vendor/lib/modules` can point at `/vendor_dlkm/lib/modules`. The ADB shell can report `Permission denied` for `qca_cld3_wlan.ko` while `/proc/modules` still lists `wlan`. The Python evidence script now preserves file metadata and sysfs access outcomes separately. `not_found_in_this_path` does not establish absence from other paths, and `metadata_visible` does not prove module readability, key trust, load success, or ABI. **Never disable SELinux or module-signature enforcement just to get a passing audit.**

## Required tests before any real flash

1. Compile and compare `baseline`, `core` and (optionally) `external` on an isolated builder; inspect all failures.
2. Back up **both slots** and retain complete ROM/recovery image and hashes. Verify fastboot/recovery access and correct slot.
3. Review and validate the boot image packager separately on extracted image data before writing.
4. Boot/rollback proof on actual device, followed by Wi-Fi, mobile data, Bluetooth, camera, USB, suspend, charging and thermal tests.
5. Test own authorized USB-WLAN and HID hardware in a controlled lab.
6. Port internal QCACLD monitor mode and injection **only** in a separate review after the stable reference.

Do not flash either slot or alter AVB, SELinux or thermal protections as part of CI. Do not wipe userdata to fix a kernel-only bootloop.
