# Release safety: NOT FLASHABLE

**Current decision: `flash_ready=false`. No part of this repository is a validated flashing workflow.** Builds produce raw kernel/module artifacts, not a proven ROM-compatible boot image or flashable NetHunter package. Neither CI PASS nor build-local module-signature validation changes this decision.

This page owns the **release policy**; [HARDWARE_EVIDENCE.md](HARDWARE_EVIDENCE.md) owns the detailed observations, comparison values and gate statuses. [EVIDENCE_TOOLS.md](EVIDENCE_TOOLS.md) owns the exact read-only inspection commands. Avoid copying their tables into this page.

## Why a build cannot be installed

1. **Exact installed-ROM provenance is not established.** Publicly downloaded and checksum-verified crDroid 13 / Android 17 OTA files are useful references, but may not be identical to the live phone's boot/vendor partitions.
2. **The source revision differs.** Current `main` uses the pinned source in [`config/upstream.lock`](../config/upstream.lock). The observed running hotdog release carries a different source suffix. Investigating a new source pin in a **draft PR** is not a merged release.
3. **Rebuilt vendor-module trust is not established.** `CONFIG_QCA_CLD_WLAN=m` with `CONFIG_MODULE_SIG_FORCE=y` demands valid, trusted module signatures and ABI compatibility. An autogenerated build certificate can verify the rebuilt modules *against itself* but may be rejected by the installed kernel; other vendor modules can also depend on an incompatible ABI.
4. **Boot/DTBO and recovery are not verified.** Boot-header v2, ARM64 `Image`, original ramdisk, included DTB, separate DTBO, AVB/rollback metadata and the active A/B slot must match the *installed* ROM. No accepted, repeatable offline image repack and recovery procedure exists.
5. **Hardware behavior is unvalidated.** USB, Wi-Fi, mobile network, cameras, Bluetooth, power, charging, suspend, and thermal behavior require controlled testing **after** all prerequisite safety gates.

## Mandatory acceptance gates

All must be independently evidenced and reviewed before any live boot experiment:

- **ROM-01:** Obtain and authenticate exact installed ROM and partition provenance, not just the public reference OTA.
- **MOD-01 / MOD-02:** Compare the original vendor WLAN and other required modules, complete `vermagic` / symbols / CRCs / dependencies, signature chains and installed-kernel trust; never mix differently signed builds.
- **BOOT-01:** Verify the exact original `boot.img` header/DTB, corresponding DTBO, ramdisk, AVB metadata and an offline reproducible packaging strategy.
- **REC-01:** Independently verify recovery access and **restorable** backups of relevant partitions for both A/B slots.
- **HW-01:** Only once upstream gates pass, record physical baseline functionality, thermal/power behavior and regression tests; then separately validate authorized NetHunter features.

The current status and evidence for each gate live **only** in the [hardware evidence ledger](HARDWARE_EVIDENCE.md). A checklist or automated report must not silently promote `UNKNOWN` to `PASS`.

## Non-negotiable safeguards

- Do **not** disable module-signature enforcement (`CONFIG_MODULE_SIG_FORCE`), SELinux, verified boot/AVB or thermal protections to mask failures.
- Do **not** strip signed modules after signing or publish `certs/signing_key.pem`.
- Do **not** infer readiness from `kernel.config`, `Module.symvers`, `modinfo`, ADB-visible names, a validated archive checksum, or `flash_ready=false` appearing in machine-readable reports.
- Do **not** flash either slot, patch kernel partitions, wipe user data, or make a restore attempt without independently reviewed evidence and a verified rollback plan.

Relevant implementation details: [build and staged-module signing](BUILD.md), [ROM board settings](CRDROID_17_BUILD_REFERENCE.md), [offline ABI triage](MODULE_ABI_AUDIT.md), [NetHunter feature acceptance](NETHUNTER_FEATURES.md). Every future release proposal must document the exact commit, images, certificates, tests and rollback procedure.
